1. Назначение

Приложение — локальный TUI-редактор музыкальной библиотеки на Rust. Оно сканирует аудиофайлы, показывает фактически записанные теги и представление библиотеки по метаданным, обнаруживает проблемы группировки, позволяет пакетно исправлять их с предпросмотром и сохранять изменения с возможностью восстановления. Первый профиль совместимости — SNOWSKY Echo Mini.

Главный сценарий: запуск из текущего каталога → фоновое чтение библиотеки → ручная проверка выбранной области → изучение raw-тегов и прогноза Echo Mini → staging → diff → подтверждение записи → проверка результата. Корень фиксирован на всё время работы TUI.

Границы первой версии

Локальные файлы MP3, FLAC, M4A/MP4, Ogg Vorbis и Opus; запись включается лишь для формата и конкретного типа тегов, поддерживаемых проверенным адаптером.

Дерево Artists / Albums / Folders / Issues, список треков, инспектор нормализованных и исходных тегов.

Поиск, выделение треков и альбомов, одиночное и массовое изменение, правила ALBUMARTIST, ARTISTS и чисел трека/диска.

Профиль Echo Mini, диагностика, staged-изменения, diff и подтверждаемая запись.

История пакетной записи и восстановление файлов; отказ от изменения неподдерживаемых метаданных вместо их незаметной потери.

CLI scan и check для запуска тех же сервисов без терминального UI. Чтение тегов при запуске TUI не запускает проверку проблем.

Экспорт на карту памяти, MusicBrainz API, переименование и перемещение файлов, обложки как редактор, акустические отпечатки и другие устройства — следующие этапы. Архитектура оставляет для них явные точки расширения.

2. Принципы

Источник истины — аудиофайлы. Индекс SQLite можно удалить и построить заново. Он не хранит единственную копию несохранённых изменений.

Разделение raw / canonical / device. Исходные теги читаются без потери многозначности и происхождения, редактор работает с нормализованными полями, профиль предлагает преобразования и предупреждения.

Минимальные изменения. При записи изменять лишь явно выбранные поля. Неизвестные и неподдерживаемые теги сохранять; если адаптер не может гарантировать сохранность, запись блокируется с понятной ошибкой.

Не верить предпросмотру устройства как факту. Правила Echo Mini являются гипотезами или результатами воспроизводимых проверок. Отдельно показывать прогноз группировки по известным тегам и предупреждения о возможных ошибках прошивки.

Предпросмотр до записи. Любое исправление формирует операции и diff. Изменение файла происходит только после явного подтверждения.

Восстановление после сбоя. Запись в медиафайлы и транзакция SQLite не образуют общей атомарной транзакции. Каждая операция имеет журнал, резервную копию и проверяемый статус.

UI не содержит файловой логики. Его состояние и команды проверяются отдельно от терминала.

Исходные файлы читаются в рабочем потоке сканера. Результаты приходят в UI сообщениями; рисование экрана, фильтрация и навигация не читают медиафайлы и не блокируются на них.

4. Структура репозитория

Один пакет с библиотечной целью `music_tag_editor` и бинарной целью `music-tui`. Библиотека экспортирует доменную модель и сервисы для других клиентов; бинарник только запускает CLI. Отдельные пакеты понадобятся лишь при независимой публикации ядра.

Зависимости направлены внутрь: domain не знает о lofty, SQLite или Ratatui; tags, library и changes реализуют операции над доменными типами; tui и cli используют общие операции сканирования и проверки. Сервисы остаются плоскими в `src/`, а индекс использует SQLite.

В TUI поток ввода идёт через `KeyEvent → KeyMap → Action → App::update`. `keymap.rs` хранит привязки клавиш для каждого режима; `action.rs` определяет смысловые действия, а `Input(char)` передаёт символы только в поля ввода. Меню действий и command palette используют тот же `Action`; индекс в них означает только позицию курсора. Цикл терминала принимает сообщения фоновых задач и перестраивает производное состояние перед отрисовкой. Функции рендеринга получают `&App` и не читают файлы, базу данных или сеть.

5. Доменная модель

Текущая модель использует `TrackId` для идентичности индексированного трека и `AudioFormat` для поддерживаемых аудиоформатов. Ноль в `TrackId` означает ещё не проиндексированный результат чтения тегов; SQLite возвращает только положительные ID. Оба типа сохраняют прежнюю форму JSON: число и строку формата. Строковый `RawTag.container` сохраняет названия контейнеров из lofty без потерь; отдельный тип появится только при наличии правил или операций, которым нужен его закрытый набор значений.

Индекс SQLite v2 обновляется последовательными транзакционными миграциями с `PRAGMA user_version`. Старые v1-базы обнаруживаются по `schema_version`; миграция сохраняет `TrackId` и полный JSON, но выносит путь, формат, размер, время изменения, fingerprint, writable, название, исполнителей, альбом и номера диска/трека в SQL-колонки. Жанры вынесены в `track_genres`, а `libraries` закрепляет корень за записями. Индексы поддерживают группировку, фильтры по исполнителю/альбому/жанру и поиск по префиксу названия. `Index::query_tracks` читает страницы проекций без десериализации JSON. Сырые теги и прочие редкие поля пока остаются в JSON. Issues вычисляются из актуальных тегов, а staged edits и journals остаются в отдельных durable-файлах: SQLite не создаёт вторую копию незавершённых операций.

struct TrackId(/* стабильный ID записи индекса */);

struct SourceSnapshot {
    path: PathBuf,
    size: u64,
    modified: SystemTime,
    content_fingerprint: Option<[u8; 32]>,
}

struct RawTag {
    container: TagContainer,      // ID3v2, Vorbis, MP4 ilst и т. д.
    native_key: String,           // TPE1, TXXX:ARTISTS, ARTIST...
    values: Vec<RawValue>,        // текст, бинарные данные, изображение
    order: usize,                 // повторяющиеся поля не схлопываются
}

struct TrackMetadata {
    title: Option<String>,
    artist: Option<String>,       // отображаемый исполнитель трека
    artists: Vec<String>,         // если реально есть отдельные значения
    album_artist: Option<String>,
    album: Option<String>,
    track: Option<NumberPair>,    // номер и optional общее число
    disc: Option<NumberPair>,
    date: Option<String>,
    genres: Vec<String>,
    artwork: ArtworkSummary,
}

struct TrackRecord {
    id: TrackId,
    source: SourceSnapshot,
    raw_tags: Vec<RawTag>,
    metadata: TrackMetadata,
    diagnostics: Vec<ParseDiagnostic>,
}

Это эскиз типов, а не готовый компилируемый API. Путь не является идентификатором трека: при повторном сканировании идентичность устанавливается индексом; операции на запись всегда повторно проверяют реальный путь и состояние файла. Поля без соответствия raw-тегу показывают происхождение (ID3v2:TPE1 и т. п.). Противоречащие друг другу контейнеры сохраняются отдельно, а нормализация выдаёт диагностическое сообщение, не выбирая значение молча.

Группировка Artists использует ALBUMARTIST, а при его отсутствии или пустом значении — ARTIST; оба исходных поля доступны в инспекторе. Группировка альбомов: основной ключ для типичного альбома — нормализованный album_artist + album, с уточнениями по каталогу и ID релиза, если он существует. Дата, разные издания и одинаковые названия требуют отдельного подтверждения при объединении; диск — часть альбома, а не независимый альбом. Various Artists и сборники обрабатываются явно. Профиль устройства использует собственный предполагаемый ключ отдельно от канонической группировки.

6. Адаптеры тегов

Интерфейс чтения возвращает все доступные контейнеры, основные значения, изображения и сведения о том, что библиотека не умеет представить или записать обратно. Интерфейс записи принимает набор операций над конкретными native-полями, а не пересоздаёт весь тег из TrackMetadata.

trait TagAdapter {
    fn read(&self, path: &Path) -> Result<TrackRecord>;
    fn capabilities(&self, format: AudioFormat) -> WriteCapabilities;
    fn validate(&self, record: &TrackRecord, edits: &[TagEdit]) -> Vec<Issue>;
    fn write_to_temp(&self, source: &Path, temp: &Path, edits: &[TagEdit]) -> Result<()>;
}

Для чтения и записи — lofty с дополнительными проверками в адаптерах для ID3v2, Vorbis и MP4. Его возможности зависят от сочетания формата файла и контейнера тегов; некоторые сочетания доступны только для чтения. Поэтому матрица возможностей строится по реальным форматам и фиксируется интеграционными тестами, а не предполагается общей для всех файлов. См. поддерживаемые форматы lofty.

Критичные случаи: несколько ARTIST, TXXX:ARTISTS против TPE1, ARTIST в нескольких контейнерах, нестандартный ID3v2 frame, бинарные поля, изображения и повреждённые теги. Перед выпуском адаптера для каждого формата тестировать байтовую сохранность аудиоданных и сохранность всех нецелевых тегов после round trip. Когда гарантия отсутствует, UI показывает read only и причину.

7. Индекс и сканирование

SQLite (rusqlite) хранит пути, файловые атрибуты, нормализованные поля, нужные для поиска raw-ключи, результаты диагностики и ссылки на историю. Включить миграции схемы; WAL использовать для конкурентного чтения UI во время обновления индекса. SQLite-транзакции защищают только индекс, не операции над музыкальными файлами. См. транзакции rusqlite.

Сканер рекурсивно обходит корни библиотеки, учитывает явные исключения и симлинки (по умолчанию не следует в сторонние каталоги), пропускает неизвестные форматы и сообщает ошибки конкретных файлов. Быстрая повторная проверка сравнивает размер и mtime; перед любой записью выполняется повторная проверка файла и, при неоднозначности, fingerprint/повторное чтение тегов. Во время работы хранится идентификатор поколения сканирования; старые сообщения фонового сканера не заменяют более свежий результат.

Сканирование прерываемо и выдаёт прогресс вместе с прибывающими треками; UI обрабатывает сообщения порциями, чтобы не задерживать ввод. Текущая TUI держит индексированные записи в памяти для навигации и поиска. Пагинация из SQLite для очень больших библиотек остаётся будущей оптимизацией.

8. Профили, правила и прогноз Echo Mini

Профиль задаёт inspect(record) -> Vec<Issue>, suggest(issue) -> Vec<ProposedEdit> и project(collection) -> DeviceView. Базовый профиль отвечает за общие ошибки. Echo Mini добавляет проверяемые эвристики: многозначные ARTIST/ARTISTS, конфликтующие ALBUMARTIST/ALBUMARTISTS, неодинаковый album artist в одном релизе, 3/12 в номерах трека, дополнительные контейнеры и потенциально проблемные изображения.

Каждое правило содержит rule_id, описание, входные поля, серьёзность, степень уверенности (observed, likely, experimental) и пример проверки на реальном устройстве. Предпросмотр показывает детерминированную группировку по выбранной модели, а рядом — отдельные риски парсера/прошивки. Попадание трека в чужой альбом невозможно гарантировать предсказанием только по тегам: у прошивки может быть состояние внутренней медиатеки. Это явно написано в UI.

Удаление ARTISTS, MusicBrainz ID или других дополнительных тегов не является автоматическим действием по умолчанию. Пользователь выбирает профиль для копии на устройство или явную операцию над оригиналом. Настраиваемый TOML-профиль может менять правила и действия, но запрещает неподдерживаемые операции адаптера.

9. План изменений и запись

Команды редактирования создают EditPlan { targets, edits, expected_snapshots }. Staging хранит полный план в локальном журнале/БД, чтобы несохранённые правки переживали перезапуск. UI показывает diff по каждому файлу и агрегат: сколько значений изменится, сколько удалится, есть ли конфликтные файлы и сколько места нужно для резервных копий.

Preflight: проверить существование файлов, права записи, свободное место, поддержку контейнера, отсутствие конфликта с исходным снимком, уникальность путей и возможность записать временный файл в том же каталоге. Если файл изменился после сканирования, остановить его запись и предложить перечитать и пересчитать diff.

Применение одного файла:

Записать в durable-журнал intent, исходный снимок и путь резервной копии.

Сделать полную резервную копию исходного файла в доступном для восстановления месте; проверить её размер/контрольную сумму. Это требуется для точного Undo, включая неизвестные теги и структуру контейнера.

Создать временный файл в каталоге назначения, применить только заданные правки, перечитать временный файл и проверить аудиопоток, целевые теги и нецелевые поля.

Синхронизировать временный файл, заменить исходный файл атомарным rename в пределах одной ФС там, где это поддерживается, синхронизировать каталог; записать результат в журнал.

Обновить индекс после успешного reread. При ошибке остановить пакет и оставить восстановимые копии и точный статус каждого файла.

Пакет из N файлов не атомарен целиком: прогресс pending / backed_up / written / verified / failed / restored хранится пофайлово. При следующем запуске незавершённый журнал предлагает продолжить проверку или восстановить файлы. Undo до восстановления сравнивает текущий fingerprint с тем, который оставила операция; при сторонних изменениях автоматическое восстановление запрещено. Политика хранения резервных копий настраивается по сроку/объёму, очистка только после явного срока и с видимым предупреждением о потере Undo. В окружении с ограниченным объёмом карты памяти запись отклоняется до получения достаточного места.

10. Устройство TUI

Ratatui рисует экран, Crossterm принимает клавиши и размер терминала. Один AppState содержит текущий экран, фокус, выборку, фильтр, выделение, очередь staged-операций, открытый диалог и прогресс задач. update(state, message) -> effects отделяет переходы состояния от IO; эффекты выполняются worker'ами и возвращаются сообщениями. См. пример архитектуры приложения Ratatui и цикл рисования.

Основной экран: слева дерево Artists / Albums / Folders / Issues / Echo Mini; в центре таблица треков с метками предупреждений; справа Inspector с вкладками Normalized / Raw / Device / Diff. В Artists строка исполнителя раскрывает строки альбомов; выбор исполнителя показывает все его треки, а выбор альбома — только треки этого релиза. Альбомы имеют стабильный ключ релиза, видимое название и счётчик треков; одноимённые релизы различаются по папке и ID релиза. Треки сортируются по диску, номеру, названию и пути, а значения без номера идут после пронумерованных. Поиск ограничен текущим исполнителем или альбомом и проверяет title, artist, album artist, album и path. Backspace сначала очищает поиск, затем поднимается от альбома к исполнителю и сворачивает его; Esc закрывает диалог либо выходит из обычного экрана. Позиции строк восстанавливаются по ключам после обновления индекса. Узкий терминал переключает панели, а не обрезает важные значения. Командная палитра, контекстные горячие клавиши и экран справки доступны без мыши. Клавиши учитывают KeyEventKind::Press, активный фокус и открытые модальные окна. Терминал восстанавливается при штатном выходе и панике.

Состояние экрана не является базой данных: список хранит ID строк и выборку, инспектор отдельно загружает один трек. У долгих действий есть progress/cancel. Отмена применения останавливает работу после завершения текущего файла; журнал сохраняет итог уже записанных файлов.

music-tui open ~/Music            # открыть/просканировать библиотеку
music-tui scan ~/Music            # обновить индекс, показать статистику
music-tui check ~/Music --profile echo-mini
music-tui check ~/Music --profile echo-mini --format json

CLI и TUI используют одинаковые адаптеры, правила и индекс. Код возврата check: 0 — ошибок заданного порога нет; 1 — обнаружены проблемы; 2 — ошибка запуска/сканирования. Конфигурация (пути и настройки), индекс и резервные копии живут в отдельных стандартных каталогах ОС; корень музыкальной библиотеки по умолчанию не засоряется служебными файлами. Формат конфигурации версионирован, секретов и сети в v0.1 нет.

В TUI проверка запускается только действием Check. Области: вся библиотека, текущая папка рекурсивно (по умолчанию), альбом или выбранные треки. Экран результатов объединяет общие проблемы и предупреждения Echo Mini с фильтром категории. Прогноз Echo Mini показывает предполагаемые artist/album и уверенность; он не применяет исправления автоматически. Меню действий и командная палитра вызывают одинаковые действия. M4A/MP4 становится доступен для записи только после проверки сохранности `mdat`, изображения и всех доступных нецелевых полей; файл с непредставимыми метаданными остаётся read-only.

Поиск дублей — отдельное ручное действие TUI и команда `music-tui duplicates ROOT --format text|json`; обе используют один сервис. Сервис группирует вероятные совпадения по нормализованным ARTIST и TITLE независимо от альбома и определяет точные копии по размеру и полному SHA-256. Пересекающиеся группы объединяются, а вычисление хешей идёт в фоновом worker с прогрессом и отменой. Экран сравнения показывает оригинальные пути, теги, формат, размер и хеш; совпадение тегов само по себе не означает одинаковую запись.

По явному подтверждению выбранный файл перемещается в `.music-tui-quarantine` внутри корня библиотеки; сканер пропускает это дерево. Перед перемещением повторно сверяются полные хеши выбранного и оставляемого файлов. Журнал карантина хранится в каталоге данных приложения и позволяет определить прерванное перемещение или возврат. Возврат допускается только при неизменном файле и свободном исходном пути; при конфликте пользователь получает статус без перезаписи. Удаления дублей нет.

13. Проверки качества

Unit: нормализация чисел и Unicode, группировка релизов, конфликты ARTIST/ARTISTS, приоритеты и уверенность правил, расчёт diff, переходы AppState.

Integration: MP3 ID3v2 и FLAC Vorbis с повторяющимися полями; M4A/Ogg/Opus — после подтверждения возможностей записи; сверка исходных и конечных тегов, аудиопотока и нетронутых полей.

Recovery: файл изменён между preview и apply; нехватка места; сбой после создания бэкапа, до/после rename; прерванный пакет; повторный запуск; запрет Undo при сторонних изменениях.

UI: тесты переходов состояния и компонентных виджетов на небольшом терминале; ручной smoke test клавиатуры и восстановления терминала.

Реальные регрессионные фикстуры Echo Mini: обезличенные пары файлов «ожидаемая группировка / фактический результат на прошивке X». Профиль меняется на основании таких примеров; отсутствие фикстуры не превращается в обещание точного поведения устройства.

CI запускает cargo fmt --check, cargo clippy --all-targets -- -D warnings и cargo test. Отдельные медленные тесты с реальными файлами выполняются по требованию, если их нельзя безопасно включить в репозиторий.

14. Порядок реализации

domain + чтение сырых тегов + минимальный CLI scan/check на MP3/FLAC; реальные фикстуры проблемных альбомов.

Индекс, группировка, правила и тесты; сравнение прогноза с тем, что показывает Echo Mini.

TUI браузер/инспектор, поиск, выделение, диагностика.

Staging, diff, точечная запись для проверенных MP3, FLAC и M4A/MP4, резервные копии и recovery.

Пакетное исправление и профиль Echo Mini; Ogg/Opus остаются read-only до отдельных проверок сохранности.

В текущей реализации M4A/MP4 входит в проверенный путь записи: изменения проходят проверку прочитанных нецелевых тегов, изображения и байтов `mdat`, затем полный backup, журнал и guarded Undo. Файлы с непредставимыми format-specific полями остаются read-only. TUI по явному действию сверяет альбом с MusicBrainz и отправляет выбранные предложения в общий staging. Экспорт создаёт проверенные копии вне корня библиотеки; переименование внутри корня использует отдельный журнал и проверяемый Undo. CLI этих новых операций пока не предоставляет.

Критерий готовности v0.1: на наборе проблемных альбомов пользователь видит исходные конфликтующие теги, понимает степень уверенности диагноза, получает воспроизводимый diff, применяет исправление и способен восстановить файлы после ошибки или ошибочного решения.
